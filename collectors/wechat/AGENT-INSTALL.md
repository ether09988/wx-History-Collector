# AGENT-INSTALL.md —— 给 AI Agent 的安装剧本

> **这份文件是写给 AI agent 的，不是写给终端用户的。**
> 用户可能把仓库地址或本地目录交给你，说：「帮我把微信聊天记录导出成 JSON」。
> 按下面六步执行，每步都有判断条件和失败处理。**没看到真实导出的条数，不要说安装成功。**

---

## 0. 先确认三件事

| 事项 | 怎么确认 |
|---|---|
| 采集器在本机的绝对路径 | 用户给的路径；没给就问。**注意是本采集器目录（`collectors/wechat/`），不是仓库根目录** |
| 操作系统 | **macOS 或 Windows**。Linux 明确不支持，别硬装 |
| 你能否在该目录执行命令 | `ls <目录>`（Windows 用 `dir`） |

目录里应该有：`README.md`、`AGENT-INSTALL.md`、`install.py`、`wx_export.py`、`setup.sh`、`wcdb-key-tool/`。
缺文件说明仓库没下全，让用户重新 clone。

如果你拿到的路径里直接就有这些文件，说明对；如果是仓库根目录（里面只有 `README.md` 和 `collectors/`），
请进到 `collectors/wechat/` 再操作。

**两个平台的关键差异，先记住：**

| | macOS | Windows |
|---|---|---|
| 解释器命令 | `python3` | `python` |
| 初始化密钥 | `setup.sh` + **管理员密码** + 可能重登微信 | `install.py --auto`，**不需管理员权限** |
| 是否改微信 | 要重签名（有风险，需用户同意） | 不改微信任何东西 |
| 额外依赖 | `lldb`（Xcode CLT） | 无 |
| Python 版本 | 3.8+ | 3.10+ |

---

## 第 1 步：环境检查

```bash
# macOS
python3 "<本采集器目录>/install.py" --json
# Windows
python "<本采集器目录>\install.py" --json
```

读返回的 JSON：

| 字段 | 含义 | 你怎么处理 |
|---|---|---|
| `ready` | 是否可以开始导出 | `true` 直接跳到第 4 步 |
| `need_setup` | 是否还没提取密钥 | `true` 走第 2 步 |
| `checks[].pass=false` | 哪项不合格 | 按 `fix` 给出下一步 |

**常见不合格项：**

- **微信数据库未找到** → 让用户先打开微信、收发几条消息，再重跑
- **微信客户端未检测到** → 确认装的是微信 4.x 桌面版
- **lldb 未安装**（仅 macOS）→ `xcode-select --install`
- **zstandard 未安装** → 可选。不装的话链接/文件消息只有占位符；要装就 `pip install zstandard`
- **Python 版本不够**（Windows 需 3.10+）→ 让用户升级 Python

---

## 第 2 步：提取密钥

### Windows（简单，可能你自己就能跑）

```powershell
python "<本采集器目录>\install.py" --auto
```

这条命令扫微信进程内存取密钥，**不需要密码、不改微信**。前提是**微信正在运行且已登录**。
如果沙箱允许，你可以直接执行；跑完检查返回里的 `ready` 是否为 `true`。

### macOS（**必须用户亲手做，你不能代劳**）

这一步要管理员密码，只能由用户在「终端」执行：

```bash
bash "<本采集器目录>/setup.sh"
```

**你必须提前跟用户讲清三件事**（这是风险告知，别跳过）：

1. 脚本会**关闭微信、给微信重新签名、再重新打开**——因为 macOS 不允许普通程序读其他进程
   内存，重签是唯一绕开的办法。
2. 需要输入一次 **Mac 登录密码**（输入时不显示字符，正常）。
3. 如果微信是 **4.1 及以上**，还要在微信里**退出登录、重新扫码登录一次**
   （新版微信只在登录那一刻计算密钥）。

另外主动提醒：**想恢复微信官方签名，重新安装一次微信即可。**

执行成功的标志是终端出现 `✅ 成功：拿到 N 个数据库的密钥`。
失败就让用户把**整段输出**发给你，据此诊断，不要猜。

---

## 第 3 步：确认密钥就位

```bash
python3 "<本采集器目录>/install.py" --json    # macOS
python "<本采集器目录>\install.py" --json     # Windows
```

确认 `ready` 为 `true`。如果不是，回到第 2 步。

---

## 第 4 步：先跑一次导出验证数据通路

```bash
# macOS
python3 "<本采集器目录>/wx_export.py" --refresh --days 1 --emit-events --out events.json
# Windows
python "<本采集器目录>\wx_export.py" --refresh --days 1 --emit-events --out events.json
```

预期最后一行：

```
OUTPUT_FILE: <输出文件的绝对路径>
```

**看到这一行才算数据通路是通的。** 常见报错：

| 现象 | 原因 | 处理 |
|---|---|---|
| `没找到微信数据库目录` | 微信没登录过/数据目录异常 | 让用户确认微信已登录 |
| `权限` 相关错误（macOS） | 密钥或目录权限异常 | 让用户重跑一次 `setup.sh` |
| `解密库刷新失败` | 密钥文件缺失或失效 | 回第 2 步重新提取 |
| `OUTPUT_FILE` 指向的文件是空数组 | 该时段确实没有消息 | 换个天数再试，**不要伪造** |

---

## 第 5 步：按用户需求导出

问清用户要什么，然后选参数：

| 用户想要 | 命令 |
|---|---|
| 最近 N 天 | `--days N` |
| 某个时间点之后 | `--since <unix 时间戳>` |
| 只要统计不要文件 | `--stat` |
| 包含公众号/系统通知 | `--include-official` |
| 单会话条数上限 | `--max-per-chat N` |

默认**不导出**公众号推送和系统通知。

---

## 第 6 步：报告结果

告诉用户这四件事：

1. 导出了**多少条消息**、涉及**多少个会话**（从命令输出的 stderr 里读）
2. 文件保存在**哪个绝对路径**
3. 时间范围
4. 如果有内容缺失（比如图片只有 `[image]` 占位），如实说明原因

---

## 红线（违反就是事故）

1. **绝不代用户输密码**，绝不尝试绕过系统权限。macOS 的 `setup.sh` 必须用户亲手跑。
2. **绝不伪造导出成功**。没看到 `OUTPUT_FILE` 和真实条数，不许说「搞定」。
3. **绝不外传** `all_keys.json`、`wechat-passphrase.json` 或导出的聊天内容。
4. **不外发、不上传**任何导出的聊天数据，除非用户明确要求并指定了接收方。
5. 微信重签是**用户自己机器上的操作**，你只负责解释原因和后果，不替他做决定。

## 参数速查

```
python wx_export.py [选项]

  --refresh            先刷新解密库（推荐）
  --days N             最近 N 天（默认 7）
  --since TS           从 Unix 时间戳开始
  --out FILE           输出文件路径
  --emit-events        输出 [{id,data}] 数组 + 打印 OUTPUT_FILE
  --max-per-chat N     单会话最多条数（默认 300）
  --include-official   包含公众号与系统通知
  --decrypted DIR      指定解密库目录
  --stat               只统计
```
